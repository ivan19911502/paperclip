# Backend SportPulse

## Когда применять

Используй навык при добавлении API, доменной логики, схем базы, миграций, интеграций и серверной обработки данных.

## Рабочие правила

- Сначала определи существующие backend-паттерны, способ конфигурации и границы модулей; не вводи альтернативный стек без причины.
- Валидируй запросы на входе схемами или типизированными валидаторами. Не считай клиентскую валидацию достаточной.
- Держи доменные правила вне тонких HTTP-обработчиков, когда это улучшает повторное использование и тестируемость.
- Используй безопасные запросы и понятные транзакционные границы. Схема должна выражать связи и ограничения целостности.
- Миграции должны быть проверяемыми и храниться в контроле версий. Избегай случайного удаления/потери данных; seed data делай повторяемыми, если это уместно.
- Возвращай предсказуемые статусы и ошибки без раскрытия секретов или внутренних деталей. Документируй важные API и их параметры.
- Защищай административные операции авторизацией и проверяй права на сервере. Используй секреты через окружение и минимально необходимые доступы к БД.
- Проверь критические happy path и ошибки релевантными тестами; не заявляй о запуске проверок, которые фактически не выполнялись.

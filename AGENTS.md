# Инструкции для SportPulse

## О проекте

SportPulse — современная спортивная медиаплатформа, ориентированная прежде всего на футбол. Платформа должна объединять спортивные новости, live-результаты, расписание и результаты матчей, статистику, лиги и турниры, команды, игроков, видео, поиск, избранное и административную панель.

## Границы workspace

- Всегда работай внутри текущего workspace. Не создавай другой workspace, репозиторий, worktree или checkout и не обходи ограничения workspace созданием нового проекта.
- Перед изменениями изучай существующий код, инструкции и статус доступных изменений.
- Сохраняй пользовательские изменения; не выполняй разрушительные действия без технической необходимости.

## Архитектура

- Учитывай существующую архитектуру и предпочитай поддерживаемые модульные решения.
- Не переписывай проект без необходимости и не навязывай новый стек без анализа.
- Разделяй UI, бизнес-логику, доступ к данным и инфраструктуру, когда это оправдано. Используй полезные абстракции без переусложнения.

## Предпочтительный стек

Предпочтительны Next.js, TypeScript, Tailwind CSS, PostgreSQL, Prisma или другой подходящий ORM и Docker Compose. Это ориентиры, а не требование заменять уже подходящий стек.

## UI и дизайн

- Создавай премиальный спортивный медиапродукт с тёмной темой по умолчанию, если спецификация не требует иного.
- Обеспечивай адаптивность для desktop, tablet и mobile, сильную визуальную иерархию, профессиональную типографику и единую дизайн-систему.
- Учитывай доступность; делай элементы управления рабочими и проектируй loading, empty и error states.
- Публичный сайт не должен выглядеть как стандартная CRUD-панель.

## Футбольная предметная область

Поддерживай понятные модели матчей, команд, игроков, лиг, турниров, расписания, результатов, турнирных таблиц, событий матчей и статистики.

## База данных и API

- Используй ясные схемы и связи; храни миграции в системе контроля версий и готовь seed data, когда это требуется.
- Не выполняй разрушительные операции с базой без необходимости; учитывай безопасность данных.
- Валидируй входные данные, обрабатывай ошибки понятно, соблюдай безопасность и документируй важные API.
- Разделяй бизнес-логику и API-обработчики, когда это целесообразно.

## Безопасность

- Не коммить секреты; используй переменные окружения.
- Валидируй и очищай входные данные. Защищай административные endpoints и используй аутентификацию и авторизацию, где это необходимо.
- Не открывай базу данных публично без явной необходимости.

## Тестирование

- Проверяй реальную функциональность: запускай релевантные unit, integration и end-to-end тесты, проверяй API и важные пользовательские сценарии.
- Не утверждай, что тесты прошли, если они не запускались. Честно сообщай об ограничениях.

## Развёртывание

- Используй Docker и Docker Compose, когда это целесообразно; поддерживай LAN-доступ, когда это требуется.
- Предусматривай health checks, постоянное хранение данных и воспроизводимое развёртывание. Храни секреты отдельно от исходников.

## Git

- Проверяй git status перед крупными изменениями и diff перед завершением.
- Не уничтожай существующие изменения; делай изменения логичными и последовательными.

## Автономная работа

- Сначала исследуй, затем изменяй. Для сложных задач самостоятельно формируй план и принимай разумные технические решения без лишних вопросов.
- Если отсутствуют API-ключи, используй полноценный демонстрационный режим, когда это возможно.
- Если запрошена реализация, не ограничивайся каркасом. Проверяй результат.

## Критерии завершения

Задача завершена, когда запрошенная функциональность реализована, релевантные проверки выполнены, обнаруженные ошибки исправлены насколько возможно, изменения проверены, ограничения указаны честно, а нужная документация обновлена.
